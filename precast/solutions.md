# Precast India Infrastructures: solutions (step 2, LIGHT)

Every screen below exists today (app CLAUDE.md, lib/navigation.ts) and is read-only. Nothing is priced. "Would measure" names the quantity, never a value. Claims about the ERP connection are future tense: the adapter is built during the pilot.

| Problem | Crestline screen today | What it would measure, from the company's ERP events | Owner of the wait | Pilot output |
|---|---|---|---|---|
| 1. Funded by others | Working Capital, P2P, Vendors | advance received against work earned out; creditor due date against payment date | Company (earning out, paying) and client (advance release) | ranked list per project |
| 2. Execution waits, billing waits | O2C, Overview | work done to bill raised; the bill step holding the wait | Company for measure, prepare, submit, invoice; client for acknowledge, certify, pay | named bills with a desk |
| 3. Dated order book | O2C, Client, Ask Crestline | per order in hand: work done to bill, bill to cash | as above | one list, re-measured on each sync |

Common to all: Alerts & Tickets turns a finding into an owner, a due date and an independent re-measure of the same figure; the owner is mailed, never on one click. Ask Crestline answers a question from the project's own measured facts; a model never produces a number.

Not offered: plant inventory (outside project cash), any saving figure, any interest, any day count.
